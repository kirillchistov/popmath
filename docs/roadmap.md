# Roadmap: тренажёр ОГЭ по математике

Документ задаёт поэтапную разработку первой версии продукта. Источники: `res/oge-math-product-prompt.md`, `res/oge-analogs-comparison.md`, заготовка `oge-math-trainer.html`.

Цель первой версии — не рынок и не «ещё один банк заданий», а рабочий контур для небольшой закрытой группы: ученик с одним профилем, родитель рядом, тьютор, который ведёт группу и сам же пишет код.

## 1. Рамка первой версии

### Для кого сейчас

Один ICP, не линейка сегментов.

| Роль | Кто | Что нужно от продукта |
|---|---|---|
| Ученик | 8–9 класс, тревога вокруг ОГЭ, пробелы за несколько лет, неуверенность, медленное решение типовых задач | Понятный ближайший шаг, короткие посильные циклы, алгоритмы вместо «пойми тему», ошибки без стыда |
| Родитель | Тревожный, не учит математику сам, хочет видеть реальность и не давить | Спокойная интерпретация раз в неделю, без отдельного приложения и без сырых баллов |
| Тьютор | На старте = разработчик | Видит когорту, добавляет задачи и опоры в простом формате, может поправить маршрут вручную |

Внутри ICP промпт выделяет четыре стартовых состояния. На первом этапе **не строим четыре отдельных продукта**. Фиксируем основной сценарий группы:

> база фрагментарная, ребёнок обучаемый, но медленный и неуверенный; рядом тревожный родитель.

Остальные состояния (почти нулевая база / сильная невнимательность / страх формата при нормальных знаниях) учитываем как **ветки одного маршрута**, а не как отдельные онбординги.

### Чего сознательно нет в v1

- монетизация, тарифы, лендинг «купи курс»;
- маркетплейс репетиторов и выбор «качества преподавателя»;
- отдельное родительское приложение;
- богатый редактор контента с картинками и геометрическим конструктором;
- LLM как обязательный слой (подсказки, разбор, маршрутизация);
- полный банк ФИПИ / импорт «Решу ОГЭ»;
- смешение с олимпиадной аудиторией.

Рыночные заявления из промпта (10–15 интервью, UX-аудит аналогов) откладываем. Сейчас источник правды — живая когорта и тьютор.

### Ограничение разработки

Один человек, стек: TypeScript, React, Next.js, BFF. Поэтому архитектура должна быть **одним приложением с ролями**, а не набором сервисов. Любая функция, которая не помогает ближайшему занятию ученика или разбору тьютора, не попадает в текущий этап.

Горизонт: учебный год 2026/27, ОГЭ весной 2027. Имеет смысл думать кварталами, а не «фазами на два года».

Каркас не пишем с нуля. Берём рабочий контур из `/Users/kirillchistov/Personal/Academic/PopArt` (Art Learning Hub): тот же соло-стек, закрытая группа, Vercel, контент в git. Подробности — в разделе 3.

## 2. Продуктовый тезис

Аналоги продают банк, курс или репетитора. У тревожного ученика с кашей в голове это не снимает главный вопрос: *что делать сегодня, и почему это ещё не доказательство, что я «тупая»*.

Первая версия делает шесть ролей из промпта, но в урезанном виде:

1. **Диагностика** — короткий стартовый проход + накопление типов ошибок, не «большой пробник».
2. **Навигация** — очередь на 1–2 недели, а не карта всего экзамена.
3. **Переводчик** — карточка-алгоритм, метафора, ловушки. Это уже есть в HTML-заготовке.
4. **Тренажёр внимания** — одна задача на экран, самопроверка, разбор «как надо / как не надо».
5. **Антистресс** — тон, дозировка, право пропустить, отсутствие публичного рейтинга.
6. **Родительский ассистент** — weekly-digest письмом или по ссылке.

Ключевой пользовательский факт, который нельзя потерять в интерфейсе:

- знания **фрагментированы**: тема «как будто проходили», но нет устойчивого алгоритма;
- типовые задачи решаются **медленно и неуверенно**;
- подросток **пропускает скучное** и живёт в чатах, мемах, рилзах;
- ошибка легко читается как приговор, а не как сигнал.

Отсюда правило продукта: *не развлекать вместо математики, а подавать математику в привычном подростку ритме коротких сообщений*.

## 3. Рекомендованная архитектура

### Откуда берём каркас: PopArt

Критичных возражений против переиспользования нет. PopArt уже решает ту же организационную задачу: закрытая учебная группа, один разработчик, Next.js на Vercel, контент в репозитории, вход без Auth.js/Clerk.

Важно не переоценить «бэкенд» PopArt. Там нет базы, ролей и прогресса. Серверная часть — это JWT-cookie (`jose`), middleware и два роута login/logout. Список людей живёт в `AUTH_USERS`. Этого достаточно, чтобы не изобретать пригласительные ссылки и отдельный сервис учёток.

| Берём как есть | Берём идею, меняем схему | Не берём |
|---|---|---|
| Next.js 15 App Router, `package.json`, `vercel.json` | JSON в `content/` → темы/задачи ОГЭ, не курсы искусства | Каталог курсов, уроки, ссылки на Google Drive |
| `lib/auth.ts`, `/api/auth/*`, `middleware.ts` | Имя cookie и ключ темы (`oge-session`, не `alh-*`) | `Lesson`, `Course`, `LibraryBlock` |
| Логин/пароль из env, сессия 14 дней | Роль в том же env: ученик или тьютор | Компоненты StAntony, карусели, hotspot-холст |
| `ThemeProvider` + CSS-переменные | Токены из `oge-math-trainer.html` | Визуал Art Learning Hub |
| Закрытый вход, без публичной регистрации | `/digest/[token]` добавить в `PUBLIC_PATHS` | `Quiz.tsx` целиком: там все вопросы на одной странице и только score |

Как переносить код: **копируем файлы в этот репозиторий**, не подключаем PopArt как submodule и не делим один деплой. Это разные продукты. Канон копирования — список в этапе 0.

### Принцип

Одно Next.js-приложение, как в PopArt. UI и тонкий BFF в одном репозитории. Контент — JSON, не зашитый JSX. Прогресс — единственный новый серверный слой; базу не поднимаем, пока тьютору не нужно видеть чужие попытки с другого устройства.

```text
Браузер ученика          Письмо родителю           Браузер тьютора
       │                        ▲                         │
       ▼                        │                         ▼
┌──────────────────────────────────────────────────────────────┐
│                     Next.js App Router                       │
│  /                    ученик: сегодня / задача / разбор      │
│  /login               вход из PopArt                         │
│  /digest/[token]      read-only недельный отчёт (без сессии) │
│  /tutor               тонкий admin, только роль tutor        │
│  /api/auth/*          login / logout из PopArt               │
│  /api/attempts        первый новый BFF: запись попытки       │
└───────────────┬───────────────────────────────┬──────────────┘
                │                               │
                ▼                               ▼
     AUTH_USERS + JWT cookie              content/topics/
     (учётки, как в PopArt)               темы, алгоритмы,
     + тонкое хранилище попыток           задачи, ловушки
                                          JSON, как курсы в PopArt
```

### Стек (рекомендация)

| Слой | Выбор | Зачем так |
|---|---|---|
| Приложение | Next.js 15 App Router + TypeScript + React 19, как в PopArt | Не собираем каркас заново |
| Стили | CSS-переменные, без Tailwind и UI-кита | Тот же приём, что в PopArt; палитра — из HTML-заготовки |
| Учётки | `AUTH_SECRET` + `AUTH_USERS` + `jose` + middleware | Закрытая группа 3–5 человек; в PopArt это уже обкатано |
| Контент | JSON в `content/topics/` | Тьютор = разработчик, правки через git, как курсы в PopArt |
| Попытки | `lib/store.ts` с тонкой реализацией; Postgres не в этапе 0–1 | Сначала интерфейс записи, не Drizzle/Neon |
| Письма | Ручная ссылка, затем простой провайдер | Weekly-digest, не CRM |
| Деплой | Vercel, тот же `vercel.json` | Один деплой, те же env, что привычны по PopArt |

Хранилище попыток наращиваем по нужде, не заранее:

1. Этап 1, один ученик рядом с тьютором — можно держать попытки в памяти процесса / локальном JSON. Это стенд, не когорта.
2. Когда тьютор смотрит с другого устройства или пишется дайджест — один JSON-документ во внешнем KV (Upstash Redis / Vercel KV). Для 5 учеников таблицы не нужны.
3. Postgres (Neon + Drizzle) — только если KV начнёт мешать выборкам. Это не старт.

LLM в критический путь не ставим. Если позже появится помощь «наводящим вопросом», это отдельный вызов из BFF с жёстким промптом и без автозачёта ответа.

### Доменная модель

Контент и прогресс разделяем. Контент стабилен и версионируется. Прогресс пишется на каждую попытку.

```text
Topic
  id, title, exam_slots[]          # например 9 / 13 или «уравнения»
  phrase, metaphor                 # «Сохраняй равновесие» / весы
  steps[]                          # алгоритм
  traps[]                          # ловушки
  supports[]                       # короткие опоры, якоря

Task
  id, topic_id
  prompt, answer, answer_norm
  kind                             # quiz | practice | check
  explain_ok, explain_trap
  review_title
  time_sec
  tags[]                           # тип ОГЭ, навык, ловушка

Attempt
  id, student_id, task_id
  raw_answer, correct
  elapsed_ms, timed_out, skipped
  error_codes[]                    # см. таксономию ниже
  self_tag                         # что сказала ученица после разбора

Student
  username                         # ключ из AUTH_USERS, как в PopArt
  display_name, role               # student | tutor
  parent_email
  start_state                      # fragment | panic | inattention | format_fear
  route                            # очередь Topic/Task на 7–14 дней

DigestToken
  student_id, token, week, expires
```

Заготовка уже содержит правильные зёрна модели: тема = фраза + метафора + шаги + ловушки; задача = ответ + «как надо» + «как не надо». Это нужно поднять в схему, а не переписывать в абстрактный LMS.

### Таксономия ошибок

Пишем в попытку, а не выводим «неверно» и забываем. Без этого нет ни маршрута, ни родительского текста.

| Код | Смысл | Как ловим на старте |
|---|---|---|
| `knowledge` | нет темы | серия ошибок одного типа + тьютор/самотег |
| `algorithm` | тема «знакома», хода нет | ошибка после подсказки по шагам |
| `inattention` | знак, не дочитала, не та величина | близость к правильному ответу, типичная ловушка |
| `calculation` | верный ход, сломанный счёт | самотег или тьютор |
| `freeze` | таймер / пропуск / пустой ответ | `timed_out`, `skipped` |
| `strategy` | начала не с того, застряла на сложной | позже, в режиме варианта |

На этапе 1 достаточно автотегов `freeze` / `inattention`(если ответ совпал с известной ловушкой) и одного вопроса после ошибки: «Что случилось?» с 4 кнопками. Тьютор может поправить тег в admin.

### Маршрутизация

Не строим адаптивную модель. Для маленькой группы хватает правил:

1. Стартовый квиз раскладывает темы на «держится / шатко / дыра».
2. На ближайшие 7 дней в очередь попадают только шаткие и дырявые темы, **одна основная + одно короткое повторение**.
3. Тема не считается закрытой по одной удаче. Нужны повторные верные попытки без подсказки и без просроченного таймера.
4. Тьютор может переставить очередь вручную.

Это закрывает инсайт промпта: ценность не в том, чтобы «объяснить всё», а в том, чтобы показать, *что сейчас даст прибавку*.

### Поверхности приложения

| Поверхность | Кто | Содержание |
|---|---|---|
| Сегодня | ученик | одна цель дня, почему она, кнопка «начать» |
| Задача | ученик | один экран, таймер по желанию, пропуск без наказания |
| Опора | ученик | алгоритм / ловушка / якорь — как короткая «сториз» до или после задачи |
| Разбор | ученик | «как надо / как не надо», самотег ошибки |
| Карта | ученик | 4–N тем, без всей спецификации экзамена сразу |
| Дайджест | родитель | токен на неделю, read-only, спокойный язык |
| Tutor | тьютор | список учеников, очередь, попытки, форма задачи |

Отдельного «курса» и ленты вебинаров нет.

### Контентный контур тьютора

Пока тьютор = разработчик:

- канон контента живёт в `content/topics/*.json`, по тому же ритуалу, что курсы в PopArt;
- `/tutor/tasks/new` — тонкая форма по той же схеме; на старте проще править JSON в git, форму добавляем на этапе 4;
- картинки и клетка — позже; в v1 текстовые задачи, как в заготовке;
- геометрия как отдельный режим не открывает этап 1, но схема темы уже должна уметь хранить `exam_slots` 15–19.

Не импортируем чужие банки целиком. Первые задачи — свои, проверяемые, с ловушкой и разбором. Качество важнее объёма: промпт и аналоги прямо говорят, что «ещё задачи» без маршрута не лечат панику.

## 4. Визуальная концепция

### Решение

**Гибрид.** Хромиум спокойный, «бумажный», из заготовки. Подача материала — короткая, как чат и сториз.

Зачем так:

- полностью teen-native (мемы, шум, стикеры) усиливает стыд у тревожного ребёнка и пугает родителя;
- полностью editorial («взрослый тренажёр») ученик пролистнёт как ещё один скучный урок;
- гибрид оставляет ощущение безопасности и даёт ритм, в котором подросток вообще согласен смотреть.

Родительский дайджест и tutor-admin **не** копируют ученический тон. Там спокойный editorial без подмигиваний.

### Что берём из `oge-math-trainer.html`

- тёплая бумага: `#f7f6f2`, поверхность `#fdfcf9`, чернила `#28251d`;
- акцент `#0d6b6f`, ошибки не красной школьной ручкой, а пыльной фуксией `#a12c7b`;
- темы как цветные знаки: уравнения / неравенства / текстовые / функции;
- одна колонка внимания, одна задача на экран;
- карточка-алгоритм, список ловушек, разбор «как надо / как не надо»;
- светлая/тёмная тема.

Шрифты заготовки (Boska + Satoshi) можно оставить на старте. Если на реальных телефонах заголовок читается слишком «журнально», заменяем display на более нейтральный гротеск, body не трогаем.

### Как выглядит ученический ритм

Экран занятия — не учебник и не лента ТикТока, а **короткий диалог**:

1. Сообщение системы: «Сегодня не весь ОГЭ. Одна штука: равновесие в уравнении».
2. Сториз из 3–5 кадров: метафора → 3 шага → одна ловушка.
3. Задача. Поле ответа. Можно пропустить.
4. Ответ системы короткой репликой, без «Молодец!!!1».
5. Два кадра памяти: как срывается / как держится.
6. Вопрос в одну строку: «Что случилось?» — четыре кнопки.

Микрокопия ученика — разговорная, конкретная, без сюсюканья и без «это должен знать каждый». Примеры тона:

- «Сначала тип, потом счёт. Иначе голова мешает себе сама».
- «Знак при переносе — твоя частая дыра. Не характер, а место, которое надо ловить глазами».
- «Пропустить можно. Это не слитая жизнь, это ход».

Запрещено в ученическом UI:

- рейтинги, лиги, публичное сравнение;
- «ты снова ошиблась», прогресс-бар на 235 тем экзамена;
- таймер, который нельзя выключить на первых занятиях;
- конфетти на каждую верную задачу;
- мемы ради мемов, не привязанные к ловушке.

### Карта прогресса

Для ученика карта — **несколько крупных островов**, не кодификатор. На старте четыре из заготовки плюс серый остров «геометрия позже». Остров имеет три состояния: держится / шатко / не трогали. Никаких процентов «готовности к ОГЭ» в первые недели.

Для родителя в дайджесте та же карта словами:

- что уже не разваливается;
- что даст прибавку на этой неделе;
- где дело не в «лени», а в типе ошибки;
- что делать дома (и чего не делать).

### Антиблокер в визуале

Страх пустого листа и геометрии — отдельные состояния экрана, не тост «попробуй ещё раз».

- пустой лист: первым кадром не условие, а «что выписать в первые 20 секунд»;
- таймер: по умолчанию выключен, включается как тренировка, а не как экзамен;
- после серии ошибок — экран паузы, не следующая задача того же типа;
- геометрия, когда дойдём, начинается с узнавания фигуры, не с доказательства.

- `lib/content.ts` и типы `Topic` / `Task` вместо `Course` / `Lesson`;
- четыре JSON из `oge-math-trainer.html` в `content/topics/`;
- пустые маршруты: сегодня, задача, разбор, карта, `/tutor`;
- `/digest/[token]` и `/login` в `PUBLIC_PATHS`;
- токены палитры из HTML-заготовки в `app/globals.css`.

Критерий готовности: тьютор и ученик входят своими логинами из `.env.local`, ученик видит пустой «Сегодня», четыре темы читаются из JSON. Сборка `npm run build` проходит.

Не делать: Postgres, пригласительные ссылки, регистрацию с улицы, перенос UI искусства, геометрический редактор.

### Этап 1. Учебный цикл из заготовки — около 7–10 дней

**Зачем.** Перенести то, что уже доказано макетом: квиз → тема → практика → разбор. Это первая ценность для ученика.

Сделать:

- стартовый квиз (сжать 15 вопросов заготовки; таймер выключаемый);
- модуль темы: фраза, метафора, шаги, ловушки;
- практика с нормализацией ответа;
- экран разбора «как надо / как не надо»;
- `POST /api/attempts` и `lib/store.ts`: записать попытку, прочитать список текущего ученика;
- самотег после ошибки.

Критерий готовности: один ученик проходит квиз и одну тему на телефоне, попытки видны тьютору списком. Хранилище может быть локальным JSON — лишь бы интерфейс `store` уже не зависел от экрана.

Не делать: адаптивную сложность, полный вариант ОГЭ, родительский текст.

Смысловая проверка этапа: ученик понимает *зачем эта задача сейчас*, а не только «верно/неверно».

### Этап 2. «Сегодня» и очередь на неделю — около 5–7 дней

**Зачем.** Закрыть главную дыру аналогов: банк есть, навигации нет.

Сделать:

- правило маршрута по результатам квиза и свежим ошибкам;
- экран «Сегодня»: одна цель, одна фраза зачем, оценка времени 10–15 минут;
- карта из 4 островов со состояниями;
- ручная перестановка очереди тьютором;
- защита от перегруза: не больше одной новой темы в день.

Критерий готовности: после квиза ученик не выбирает тему из меню, а получает следующий шаг. Тьютор может сказать «на этой неделе не функции, а знаки в уравнениях».

### Этап 3. Внимание, скорость, антиблокер — около 5–7 дней

**Зачем.** У этой группы результат часто ломается не на «не знаю формулу», а на невнимании, ступоре и медлительности.

Сделать:

- разделение режима: без таймера / мягкий таймер / экзаменальный;
- отдельный мини-навык самопроверки (чеклист перед сдачей ответа);
- автотег `freeze` и `inattention` по ловушкам;
- экран паузы после серии отказов или ошибок;
- сценарий «страх пустого листа» для текстовых задач.

Критерий готовности: в попытках видно не только score, а *почему* медленно или пусто. Ученик может потренировать самопроверку отдельно от новой темы.

Геометрию сюда ещё не тащим, кроме как задел в квизе (вопросы 15–19 заготовки можно оставить диагностическими).

### Этап 4. Тонкий tutor-admin и материалы — около 5–7 дней

**Зачем.** Тьютор должен добавлять задачу за 5–10 минут, не открывая редактор кода. При этом канон остаётся простым.

Сделать:

- список когорты: активность, доминирующий тип ошибки, тема недели;
- форма задачи: условие, ответ, «как надо», «ловушка», тема, время;
- форма опоры: 3–5 шагов, метафора, якорь;
- возможность посадить задачу в очередь конкретному ученику;
- правка тега ошибки на попытке.

Критерий готовности: новую задачу тьютор добавляет из браузера и сразу даёт её ученику. Git-контент и admin-контент не разъезжаются по схеме.

Не делать: WYSIWYG, загрузку вариантов Word, совместное редактирование.

### Этап 5. Родительский weekly-digest — около 4–6 дней

**Зачем.** Родитель перестаёт допрашивать ребёнка и тьютора. Отдельное приложение не строим.

Сделать:

- еженедельная страница по токену и/или письмо;
- блоки: что уже держится; что в работе; какой тип ошибки главный; что делать дома; чего не делать;
- язык без методического жаргона и без «ребёнок плохо старается»;
- ручная отправка тьютором + простейший cron;
- срок жизни токена (неделя–две).

Критерий готовности: родитель за 2 минуты понимает картину недели и не пишет «ну что, как она?». Ученик не видит родительские формулировки в своём UI.

### Этап 6. Геометрия и расширение карты — около 8–12 дней

**Зачем.** Промпт отдельно фиксирует ступор на геометрии. После того как контур живой, это следующий предметный риск группы.

Сделать:

- остров «геометрия» с узнаванием типа (углы, треугольник, площадь, клетка);
- опоры «как узнать, что это за фигура» до решения;
- текстовые задачи на клетчатой бумаге — пока статичные картинки, не конструктор;
- отдельный антиблокер «страх геометрии»: сначала 2 минуты узнавания, потом счёт.

Критерий готовности: геометрия не появляется как 19 страшных номеров, а как 3–4 узнаваемых сюжета.

### Этап 7. Экзаменационная стратегия — по живой группе

Только если этапы 1–5 уже в привычке.

- короткий сборный набор (не полный пробник);
- порядок «сначала то, что держится»;
- разбор несоответствия «в школе 4, в формате ОГЭ дыра»;
- разговор о пороге / уверенной 4 без обещания балла.

Полный пробник на время в первой четверти работы с тревожной группой не запускаем.

## 6. Что считать успехом, пока нет монетизации

Не балл ОГЭ и не число решённых задач. Для маленькой группы смотрим то, что промпт называет ранними сигналами:

| Сигнал | Как увидеть |
|---|---|
| Меньше отказов «даже не начну» | доля `skipped` / пустых на старте задачи |
| Меньше глупых срывов | доля `inattention` среди ошибок |
| Появляется алгоритм | верные решения после просмотра опоры, затем без неё |
| Регулярность без войны | 3 коротких захода в неделю важнее одного «марафона» |
| Родитель спокойнее | меньше срочных сообщений тьютору после дайджеста |
| Скорость типового | медиана `elapsed_ms` на задачах уже знакомого типа |

Тьютор раз в две недели смотрит эти числа вручную. Отдельная аналитическая платформа не нужна.

## 7. Порядок внедрения с живыми людьми

Разработка и обкатка идут вместе, иначе контент и тон поедут мимо подростков.

1. Собрать 1–2 ученика своего ICP и одного родителя ещё на этапе 1. Не ждать «готового продукта».
2. Первые занятия тьютор сидит рядом (или в созвоне) и смотрит, где текст скучный, где стыдно, где непонятно, куда жать.
3. Дайджест сначала отправить одному родителю как черновик и спросить: «что стало яснее, что наоборот тревожит».
4. Новые темы не добавлять, пока не закрыт цикл «сегодня → задача → разбор → виден тип ошибки».
5. Геометрию и пробник открывать только когда ученик уже верит, что уравнения ему поддаются.

## 8. Зафиксированные развилки

| Вопрос | Решение |
|---|---|
| Тон ученика | Гибрид: бумажная основа заготовки + чат/сториз-подача |
| Родитель | Weekly-digest (письмо или ссылка), без отдельного приложения |
| Тьютор | Разработчик; контент JSON в git + тонкий admin позже |
| Каркас | Копия PopArt (auth + Next + Vercel), не общий репозиторий |
| LLM | Вне критического пути первой версии |
| Регистрация | `AUTH_USERS`, как в PopArt; без публичной формы и без invite-ссылок |
| Попытки | Сначала `lib/store.ts` + KV/локальный JSON; Postgres не в старте |
| Предметный старт | 4 темы заготовки, геометрия — этап 6 |
| Монетизация | Не проектируем |

Если группа вырастет или тьютором станет другой человек, это отдельный разговор: появятся нормальный редактор, роли, возможно отдельный родительский вход. Сейчас это преждевременно.
